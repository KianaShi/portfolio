§1

Verdict

Recommend x = 0.58

Not x=0.70 as originally suspected. The five requested checkpoints (0.40/0.55/0.70/0.85/1.00) don't actually contain a clean answer: 0.40 has the mullion cutting straight through the building's silhouette, and everything from 0.70 up already clips Rainier's peak by measured pixel overlap — confirmed by diffing against a no-building reference, not eyeballed. A narrower search between 0.55 and 0.70 found the actual transition: Rainier overlap starts at 0.60 (131px) and grows fast (0.65→928px, 0.70→1726px), while a clean, non-touching mullion gap only opens up around 0.58. x=0.58 is the last value with both a real mullion gap AND zero measured Rainier overlap, confirmed at rest and at both parallax extremes.

§7

Recommendation

x = 0.58

Only buildingRoot.position.x changes to reach this state (via window.__buildingTest.setX pattern) — scale (0.035), y/z, rotation (15°), P2 materials, the 9 hardcoded light positions/colors/intensity, and the Seattle background/parallax are all exactly as Round 4 left them. Not yet written into tools/_bgtest/building-test.js's X_PRESETS as a default — this report is measurement + recommendation only, per this round's brief.

  1. 0.58 is a local optimum from a 0.55–0.70 search at 0.02–0.05 granularity, not an exhaustively fine-grained result. If finer tuning is wanted later, the real constraint to search against is the Rainier-overlap transition (clean at 0.58, first contact at 0.60) — there is very little room to move further right without measurement, not guesswork.
  2. The originally-suspected sweet spot (0.70) is off the table: it clips Rainier by a measurable, non-trivial margin (1,726px) even at rest, before parallax makes it worse.
  3. If a future round changes scale, y, z, or rotation, this x value and the whole 0.55–0.70 measurement table should be treated as stale — the mullion/Rainier/PC positions are all fixed in world space, so any change to the building's own transform shifts these clearances.
